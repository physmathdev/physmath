oldtube

Version 1.2.2 · physmath
iOS 5.0 – 10.x Tweaks iphoneos-arm Free

About

oldtube keeps the classic Google YouTube app working without a backend server. It supports YouTube 1.0.0 through 1.4.0 and 2.0.0 on iOS 5 through iOS 10, and restores sign-in, the signed-in home feed, subscriptions, personal recommendations and watch history.

There is no analytics, crash reporting or telemetry.

What's new in 1.2.2

  • Quality menu in the player bar. A gear button now sits next to the subtitles (CC) button, like in current YouTube. It opens a dark bottom sheet with Auto / 720p / 360p / 240p / 144p and ticks the active choice. Picking a height really limits the adaptive stream ladder, so it takes effect the next time a video is opened.
  • Playback no longer stalls when YouTube omits the selected formats. Sometimes the server's playback cookie names no video/audio format (itag 0). oldtube now reads the formats from the media headers that actually arrive, instead of dropping every media part and failing with “not enough data to start stream”.
  • Google sign-in fixed on iOS 5/6. The embedded sign-in web view no longer crashes on its WebThread: the User-Agent override used to call the original method through a selector with a different signature.
  • The quality sheet rotates correctly. It is attached to the player's rotated view hierarchy instead of the window, so it stays level in landscape and portrait.

What's new in 1.2.1

  • Playback no longer freezes after the first minute or two. The player used to ask YouTube for every available video and audio format at once, but its local stream can only ever serve the one format it started with. YouTube would quietly switch to a different format mid-video, the new media parts no longer matched the running stream and were dropped, and playback stalled as soon as the initial buffer ran out. The player now locks on to the exact format it is playing, so longer videos keep going instead of freezing.

What's new in 1.1.0

  • Sign-in works again (fixes “This browser or app may not be secure”). The sign-in screen runs inside an embedded web view, and it used to identify itself with the YouTube app's own User-Agent. Google treats that as an insecure embedded browser and refuses to authenticate it. The web view now presents a normal mobile Safari identity, so Google's sign-in flow completes. This affects only the web view — the app's API requests still send the client User-Agent they always did.

What's new in 1.0.9

  • History actually opens. The new backtrace showed the crash happened inside oldtube's own POST response wrapper, where the app tried to invoke a block that had already been released (SIGSEGV at 0x0). The wrapper is now applied only to the requests whose responses oldtube really caches (subscriptions and channels). Everything else — including the History request — is handed to the client untouched, so there is nothing left to crash there.
  • Better crash evidence. The crash log now dumps the CPU registers (r0–r12, sp, lr, pc) alongside the backtrace, and the response wrapper records what it did, so any future crash can be identified immediately.

What's new in 1.0.8

  • History crash fixed. The watchdog backtrace showed the app invoking a response block through a NULL pointer (SIGSEGV at 0x0). The classic client only retains response blocks instead of copying them, so the wrapper oldtube passed for History went stale on the stack before the (slow) response arrived. Response blocks are now real heap blocks, which removes the crash at the source.
  • Emergency History mode. New switch under Settings → oldtube → Experimental Settings. When enabled, History is served purely from the locally recorded watch history and never touches the request path, so the screen is guaranteed to open even if a future YouTube change breaks the normal flow again.

What's new in 1.0.7

  • History diagnostics. When the History screen is loaded, the exact page it receives (entry count and classes, totalResults/entriesPerPage, and sample video IDs) is now written to /var/mobile/Media/oldtube_history.log and to the system log.
  • Real backtraces. The YouTube app installs its own crash reporter at launch, which was replacing oldtube's. That reporter is now disabled and oldtube's signal/exception handler is re-armed right before the History page loads, so the crash finally produces a readable backtrace in /var/mobile/Media/oldtube_crash.log.
  • History fix in progress. This build is a diagnostic step to pin the remaining History crash precisely; no other behaviour changed.

What's new in 1.0.6

  • Crash reports on stderr. The crash handler now mirrors its report to stderr, so the backtrace can be read with idevicesyslog even though the app container is not reachable over AFC.
  • Startup log probe. The crash log is created at launch, so log collection no longer depends on a crash happening first.

What's new in 1.0.5

  • History crash fixed properly. The merged History page now always holds a mutable entry list, so the feed controller can no longer raise “mutating method sent to immutable object”. The local-only fallback reuses the same page class the app's parser produced.
  • More reliable crash logging. The crash handler now runs on a real alternate signal stack, so even a stack-overflow crash produces a readable oldtube_crash.log.
  • iOS 5–10 only. The bundled YouTube 2.0.0 is 32-bit (armv7); iOS 11+ cannot run 32-bit apps, so this package intentionally stays on iOS 5–10.

What's new in 1.0.4

  • 720p in the player. A quality button in the player opens Auto / 720p / 480p / 360p. Switching is instant and does not restart playback.
  • Fixed History crash. Local watch history is merged into the real History page instead of replacing it, and entries without a channel no longer trigger a broken channel lookup.
  • YouTube included. The package now installs YouTube 2.0.0 itself, with the oldtube icon, so one install sets everything up.
  • Crash logging. If the app still crashes, a report is written to the app's Documents folder as oldtube_crash.log (and to /var/mobile/Media/oldtube_crash.log when allowed).

What's new in 1.0.2

  • Endless personal recommendations. The “What To Watch” feed keeps loading related videos instead of stopping after the first page, and it never falls back to global trending results.
  • Normal watch history. Watched videos are recorded through the app's playback tracking and appear in the History tab, with paging for older entries.
  • Focused YouTube 2.x support. The tweak covers YouTube 1.0.0–1.4.0 and 2.0.0.
  • Bundled n/sig solver. Playback signatures work offline, with an automatic weekly refresh when the solver is updated.
  • New identity. A new name, a new retro-TV icon and a cleaned-up preferences panel. Analytics, crash reporting and debug mail are gone.

What it does

  • Fixes Google sign-in so accounts can be added again
  • Restores the signed-in home feed and personal recommendations
  • Loads subscription uploads, favorites, watch later and uploaded videos
  • Keeps watch history between launches
  • Handles feed paging without crashes or duplicate rows
  • Provides preferences for playback quality and feed behavior

What doesn't work

  • Purchases
  • Age-restricted content in some regions
  • The Add Channel button, which opens a channel list with no sensible default

Install

  1. Add the source below in Cydia, Sileo or Zebra.
  2. Search for oldtube and install it.
  3. Respring the device.
Add to Sileo Add to Cydia

The package installs YouTube 2.0.0 and the tweak together, replaces any previous oldtube package, and keeps existing settings and history.

Requirements

Jailbroken iOS 5.0 – 10.x with MobileSubstrate and PreferenceLoader. Supported YouTube versions: 1.0.0, 1.0.1, 1.1.0, 1.2.1, 1.3.0, 1.4.0 and 2.0.0.
